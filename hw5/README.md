# REST-сервис для управления заказами и историей их статусов

## API

В сервисе реализованы методы для создания и получения заказов, изменения статуса и просмотра истории изменений:

* ```POST /api/v1/orders``` - создание заказа
* ```GET /api/v1/orders``` - получение списка заказов
* ```GET /api/v1/orders/{id}``` - получение заказа по идентификатору
* ```PATCH /api/v1/orders/{id}/status``` - изменение статуса заказа
* ```GET /api/v1/orders/{id}/history``` - получение истории статусов заказа
* ```GET /health``` - проверка доступности сервиса

При создании заказа сервис автоматически:

* назначает последовательный id
* устанавливает статус ```new```
* рассчитывает общую стоимость заказа
* сохраняет время создания
* добавляет начальный статус в историю

Поддерживаются статусы ```new```, ```processing```, ```completed``` и ```cancelled```

Допустимые переходы:

* ```new → processing```
* ```new → cancelled```
* ```processing → completed```
* ```processing → cancelled```

Статусы ```completed``` и ```cancelled``` являются конечными

Также описаны ошибки:

* ```200``` - успешное получение или изменение
* ```201``` - успешное создание
* ```400``` - некорректные входные данные
* ```404``` - заказ не найден
* ```409``` - недопустимый переход статуса
* ```500``` - внутренняя ошибка сервера

## Кодогенерация

В качестве HTTP-контракта используется OpenAPI-спецификация ```internal/transport/openapi.yaml```

На её основе через oapi-codegen генерируются структуры запросов и ответов, HTTP-обработчиков и маршрутизация для Chi.

Для повторной генерации кода используется команда:

```bash
cd internal/transport
go run github.com/oapi-codegen/oapi-codegen/v2/cmd/oapi-codegen@v2.6.0 --config oapi-codegen.yaml openapi.yaml
```

## Валидация

Валидация выполняется на уровне HTTP-транспорта и service

HTTP-слой обрабатывает JSON-тело запроса и параметры пути. Некорректный JSON или идентификатор возвращает ошибку ```400``` в общем формате API

На уровне service проверяются бизнес-правила:

* заказ должен содержать хотя бы одну позицию
* название позиции не может быть пустым
* количество и цена должны быть положительными
* итоговая стоимость не должна переполнять ```int64```
* идентификатор заказа должен быть положительным
* статус должен входить в список допустимых значений
* изменение статуса должно соответствовать разрешённым переходам

Итоговая стоимость рассчитывается как сумма произведений цены на количество для каждой позиции

## Хранение данных

Заказы хранятся в памяти процесса. Репозиторий защищён через ```sync.RWMutex```, поэтому чтение и изменение данных безопасны при конкурентных запросах

После перезапуска сервиса все созданные заказы удаляются, а последовательность идентификаторов начинается заново

## Запуск

По умолчанию сервис запускается на порту ```8080```:

```bash
go run ./cmd/orders
```

Адрес можно изменить через переменную окружения ```HTTP_ADDR```:

```bash
HTTP_ADDR=:8090 go run ./cmd/orders
```

После запуска сервис будет доступен по адресу ```http://localhost:8080```

Swagger UI:

```
http://localhost:8080/swagger/index.html
```

OpenAPI-спецификация:

```
http://localhost:8080/swagger/openapi.yaml
```

## Тесты

Для запуска всех тестов используется команда:

```bash
go test ./...
```

Для дополнительной проверки конкурентного доступа можно использовать race detector:

```bash
go test -race ./...
```

## Пример работы

Создание заказа:

```bash
curl -i -X POST http://localhost:8080/api/v1/orders \
  -H "Content-Type: application/json" \
  -d '{
    "customer": "Alice",
    "items": [
      {
        "name": "Keyboard",
        "quantity": 2,
        "price": 500000
      },
      {
        "name": "Mouse",
        "quantity": 1,
        "price": 100000
      }
    ]
  }'
```

В ответ сервис вернёт созданный заказ с идентификатором, общей стоимостью, текущим статусом и историей:

```json
{
  "id": 1,
  "customer": "Alice",
  "items": [
    {
      "name": "Keyboard",
      "quantity": 2,
      "price": 500000
    },
    {
      "name": "Mouse",
      "quantity": 1,
      "price": 100000
    }
  ],
  "total_price": 1100000,
  "status": "new",
  "created_at": "2026-11-27T12:00:00Z",
  "history": [
    {
      "status": "new",
      "changed_at": "2026-11-27T12:00:00Z"
    }
  ]
}
```

Изменение статуса:

```bash
curl -i -X PATCH http://localhost:8080/api/v1/orders/1/status \
  -H "Content-Type: application/json" \
  -d '{"status":"processing"}'
```

Получение истории статусов:

```bash
curl -i http://localhost:8080/api/v1/orders/1/history
```

Получение списка заказов:

```bash
curl -i http://localhost:8080/api/v1/orders
```

Запрос несуществующего заказа:

```bash
curl -i http://localhost:8080/api/v1/orders/999
```

Сервис вернёт ответ ```404 Not Found```:

```json
{
  "error": "order not found",
  "code": "ORDER_NOT_FOUND"
}
```
